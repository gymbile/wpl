# WPL 1.9.0 Vocabularies — Implementation Plan

> Spec: `docs/superpowers/specs/2026-07-07-wpl-1.9.0-goal-dietary-vocabularies-design.md`
> Additive, non-breaking. Recommended goal-category + dietary-tag vocabularies, soft-validated.

## Release order (6 repos)

1. **`wpl` (this repo)** — schema + data vocab files + spec + conformance + CHANGELOG → tag **v1.9.0**. *(No publish gating — do first.)*
2. `wpl-validator-ts` (npm) — soft-warn on off-list values; bump 1.9.0; publish (OIDC).
3. `wpl-validator-ex` (Hex) — parity; publish. **Gated:** `HEX_API_KEY` may be expired → may need human.
4. `wpl-ai` — assess only; change + publish iff the DSL surfaces goal category / dietary tags.
5. `wpl.dev` — docs + version bump.
6. `gymbile_backend` — upgrade deps, re-vendor, delete gymbile-local goal list (read from lib), repoint `Intake.diet_vocab`, keep drift-guards.

Steps 2–6 depend on step 1 being released. **This plan implements step 1**; later steps are separate increments once v1.9.0 is tagged.

## Step 1 — `wpl` repo v1.9.0 (the actionable unit)

**Conventions to follow (verified):** `data/*.json` files carry a `"version"` field and a companion `*.schema.json`; documented in `data/README.md`. CI (`.github/workflows/ci.yml`) uses `ajv-cli@5` to JSON-parse everything under `schema examples conformance data` and validate `conformance/valid/*` + `examples/*` against `schema/v1.schema.json`. Validation = the test.

### 1a. Recommended goal-category vocabulary

- **`data/goal-categories.json`** (new):
  ```json
  {
    "version": "1.0.0",
    "categories": [
      { "id": "weight_loss",     "label": "Weight loss" },
      { "id": "muscle_gain",     "label": "Muscle gain" },
      { "id": "endurance",       "label": "Endurance" },
      { "id": "strength",        "label": "Strength" },
      { "id": "flexibility",     "label": "Flexibility / mobility" },
      { "id": "mental_wellness", "label": "Mental wellness" },
      { "id": "nutrition",       "label": "Nutrition / dietary" },
      { "id": "habit",           "label": "Habit formation" },
      { "id": "general_fitness", "label": "General fitness" },
      { "id": "custom",          "label": "Custom (off-list escape hatch)" }
    ]
  }
  ```
  (Union of the WPL-documented categories + `general_fitness`; `custom` = documented escape hatch.)
- **`data/goal-categories.schema.json`** (new): JSON Schema — object with `version` (string) and `categories` (array of `{id (pattern ^[a-z0-9][a-z0-9_-]*$), label, description?}`), `additionalProperties:false`.
- **`schema/v1.schema.json`** — `Goal.category` (line ~193): keep `{"type":"string"}`, add a `description` referencing the recommended vocabulary (`data/goal-categories.json`) and that unknown values are allowed (validators SHOULD warn). Do **not** add an `enum`.

### 1b. Dietary-tag vocabulary + carrier field

- **`data/dietary-tags.json`** (new):
  ```json
  {
    "version": "1.0.0",
    "tags": [
      { "id": "vegetarian",  "label": "Vegetarian" },
      { "id": "vegan",       "label": "Vegan" },
      { "id": "gluten_free", "label": "Gluten-free" },
      { "id": "dairy_free",  "label": "Dairy-free" }
    ]
  }
  ```
- **`data/dietary-tags.schema.json`** (new): same shape as the goal-categories schema (`version` + `tags` array of `{id, label, description?}`).
- **`schema/v1.schema.json`** — `NutritionActivity` (line ~822): add optional property
  `"dietary_tags": { "type": "array", "items": { "type": "string" }, "description": "Recommended values in data/dietary-tags.json; unknown values allowed (validators SHOULD warn)." }`.
  (NutritionActivity uses `additionalProperties:false`, so the property MUST be declared for fixtures to validate. Do NOT add it to `required`.)

### 1c. Docs

- **`data/README.md`** — add bullets for `goal-categories.json` and `dietary-tags.json` (normative recommended vocabularies; soft-validated; consumers vendor + codegen).
- **`spec/SPECIFICATION.md`** — a short subsection documenting: goal `category` is free-form but SHOULD use `data/goal-categories.json`; `NutritionActivity.dietary_tags` is optional and SHOULD use `data/dietary-tags.json`; validators SHOULD warn (not reject) on off-list values.

### 1d. Conformance

- **`conformance/valid/goal-general-fitness-and-dietary-tags.json`** (new): a minimal valid plan with a goal `category: "general_fitness"` and a `nutrition` activity carrying `dietary_tags: ["vegan"]`. Must validate against `schema/v1.schema.json` via ajv.
- (Optional, only if the conformance suite has a warning channel — it does not appear to — skip a "warns on unknown" fixture; warnings are validator-lib behavior, covered in steps 2–3.)

### 1e. CHANGELOG

- **`CHANGELOG.md`** — new `## [1.9.0] — <date>` above `[1.8.0]`:
  ```
  ### Added
  - Recommended goal-category vocabulary (`data/goal-categories.json`) incl. `general_fitness`; `Goal.category` stays free-form, validators SHOULD warn on off-list values.
  - Dietary-tag vocabulary (`data/dietary-tags.json`) and optional `NutritionActivity.dietary_tags` field.
  ```
  Non-breaking (additive) → minor bump.

### 1f. Validate + PR

- Run the CI validation locally: `npx ajv-cli@5 compile -s schema/v1.schema.json --spec=draft2020 --strict=false`, then `ajv validate -s schema/v1.schema.json -d "conformance/valid/*.json" --spec=draft2020 --strict=false -c ajv-formats` (mirror ci.yml flags), and JSON-parse the new `data/*.json`. All must pass.
- Commit in logical chunks; open a PR to `main`. Do NOT tag v1.9.0 or publish anything — that's a human release step after review.
