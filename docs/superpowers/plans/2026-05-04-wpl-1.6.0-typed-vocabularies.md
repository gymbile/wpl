# WPL 1.6.0 — Typed Vocabularies (A–H Pass) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tighten the WPL v1 schema with medically-relevant typed vocabularies — contraindication severity & clearance, structured cardio interval durations, AMRAP/to-failure prescription flags, structured progress measurements, recovery modalities — released as additive **v1.6.0** across schema, both validators, and compiler.

**Architecture:** All changes are additive in 1.x (no breaking changes). Bump schema `version` const to `1.6.0`, mirror the schema file across the 4 repos, add conformance fixtures (valid + invalid) per new field, then sync the static copies in `wpl.dev`. Validators are largely schema-driven (Pass 1 = JSON Schema), so the bulk of work is the schema + conformance suite. Compiler (`wpl-ai`) gets vocabulary updates so it can emit the new shapes.

**Tech Stack:** JSON Schema 2020-12, TypeScript (ajv-based validator + compiler), Elixir (`ex_json_schema`-based validator), Astro (wpl.dev playground).

**Repos touched:** `wpl/` (canonical schema + spec + conformance), `wpl-validator-ts/`, `wpl-validator-ex/`, `wpl-ai/`, `wpl.dev/`.

**Out of scope already shipped in 1.3–1.5:** PhaseType enum, `is_deload`, tempo as oneOf string|object, per-kg macros, zone_model, athlete_thresholds, MuscleGroup/MovementPattern enums, condition prefix vocabulary, sub-plan composition.

- **Typed progress measurements.** `Checkpoint.measurements[]` items now accept either a free string (back-compat) or a `MeasurementSpec` referencing the new `MeasurementMetric` enum (24 standardized metrics: body composition, hemodynamic, cardiorespiratory, strength, flexibility, sleep, RPE) and a `Questionnaire` enum (PHQ-9, GAD-7, IPAQ, PSQI, PSS-10, Borg CR-10, session RPE).
